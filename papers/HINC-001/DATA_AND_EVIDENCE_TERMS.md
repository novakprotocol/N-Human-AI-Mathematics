# HINC-001 Data and Evidence Terms

The machine-readable receipts, exact finite outputs, logs, source ledgers, test records, and artifact identities are published to support verification and scientific criticism.

## Permitted scholarly use

Reviewers may inspect, cite, compare, and reproduce the evidence for the purpose of evaluating `HINC-001`. Independent reports should preserve source identities and clearly distinguish reproduced data from project-supplied data.

## Integrity requirements

Do not:

- edit a receipt while retaining its original hash or identity;
- omit failed runs when describing the formal history;
- combine outputs from different source commits under one result identity;
- represent project-internal evidence as external institutional validation;
- infer mathematical correctness solely from a matching hash.

## Personal and confidential data

The public package is not intended to contain personal records, private correspondence, credentials, or confidential third-party material. Any such discovery should be reported immediately and public distribution paused until corrected.

## Derived datasets

A derived evidence table should identify:

- project source commit;
- derivation method;
- software and environment;
- whether expected answers were available;
- output hash;
- limitations.

## Archival release

A future DOI release may place selected evidence under more permissive data terms. Until then, repository access is for review and ordinary scholarly use, not an implied unrestricted data license.
